This module extends Odoo's role-based security system to provide
granular, role-based visibility control over PDF and QWeb Reports:

1. It introduces the ability to configure "Allowed Reports" on Access
   Rights.
2. It strictly enforces a "Deny by Default" policy, ensuring that users
   can only print the specific reports explicitly permitted by their
   assigned Roles.
3. Automatically populates existing report access during installation to
   prevent disruption.

Configuration
=============

To configure role-based report access:

1. Go to **Settings > Users & Companies > Roles** and select the Role
   you want to configure.
2. Under this Role, identify the implied Groups that grant access to the
   relevant models.
3. Edit the Group's **Access Rights** tab.
4. For the model access rules, specify the permitted reports in the
   **Allowed Reports** field.

All permitted reports from the groups implied by a user's active Roles
will be automatically aggregated and dynamically enforced.

Usage
=====

Once report access is configured for a Role:

1. Assign the Role to a user (and ensure the Role is active).
2. The user navigates to the target model (e.g., Sales Orders).
3. Under the **Print** action menu, the user will only see the specific
   reports that have been explicitly allowed by their active Roles. All
   other reports are hidden.

**Note on New Reports:** Under the "Deny by Default" model, installing
new modules that add reports will hide those reports from all users
(except superusers) until they are explicitly added to the allowed
reports of the appropriate Role's implied groups.
